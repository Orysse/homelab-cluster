ABE.LC
======

A personal homelab built around microvm.nix.


GOAL
----

This project explores microvm.nix as a lightweight, fully declarative
alternative to a conventional hypervisor for running a small Kubernetes
cluster at home. Every machine, from the physical host to the virtual
nodes, is defined in a Nix flake and can be rebuilt from source.


WHY MICROVM.NIX
---------------

Traditional virtualization stacks treat a virtual machine as a disk image
that must be installed, maintained, backed up and migrated. microvm.nix
takes a different approach: a virtual machine is a NixOS configuration,
built and started by the host like any other system service.

This fits the aim of the project: no hand-maintained state, and
infrastructure that can be reviewed, versioned and reproduced exactly.


WHAT IT DOES
------------

microvm.nix builds lightweight NixOS virtual machines from a Nix
configuration and runs them under a minimal hypervisor (QEMU, Firecracker,
cloud-hypervisor, among others). The host's Nix store is shared with the
guests, so no root disk image is required, and the root filesystem can be
kept in memory. Each virtual machine runs as a systemd service on the host
and is declared alongside the host configuration.


PROS AND CONS
-------------

+--------------------------------------+--------------------------------------+
| Pros                                 | Cons                                 |
+--------------------------------------+--------------------------------------+
| Fully declarative: the configuration | Requires familiarity with Nix and    |
| is the machine                       | NixOS                                |
+--------------------------------------+--------------------------------------+
| Reproducible: rebuilds are identical | Smaller ecosystem and community than |
|                                      | established hypervisors              |
+--------------------------------------+--------------------------------------+
| No disk images to maintain or back   | No management interface; all changes |
| up                                   | go through code                      |
+--------------------------------------+--------------------------------------+
| Fast boot and low overhead           | Persistent data must be planned      |
|                                      | explicitly (volumes, shares)         |
+--------------------------------------+--------------------------------------+
| Versioned, reviewable infrastructure | Guests are tied to NixOS and to the  |
| with rollback                        | host's Nix store                     |
+--------------------------------------+--------------------------------------+
