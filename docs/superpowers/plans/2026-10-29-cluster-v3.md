# Cluster v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `homelab-cluster` (and the k3s/nuc1 parts of `homelab-nix`) as v3: one Cilium data plane, Flux Operator, OpenBao configured by self-initialization only, PostgreSQL on CloudNativePG, CrowdSec bans enforced in eBPF, OpenTelemetry collection, same services for the kept apps.

**Architecture:** Spikes first, on the live cluster, to settle the four risky unknowns. Then v3 is built on a `v3` branch in both repositories, validated statically by CI, and applied in one hard cutover: the k3s data is wiped, Flux rebuilds everything from git, data is imported (PostgreSQL from nuc1 by CNPG, OpenBao KV from an export, NFS volumes re-attached). Electricity (Kepler) and documentation come last.

**Tech Stack:** NixOS + microvm.nix, k3s (stripped), Cilium (CNI, kube-proxy replacement, LB-IPAM, L2 announcements, Gateway API, policies, Hubble), Flux Operator, cert-manager, OpenBao, External Secrets, CloudNativePG + Barman Cloud plugin, Garage, local-path-provisioner, csi-driver-nfs, Pocket-ID, oauth2-proxy, Headlamp, CrowdSec, OpenTelemetry Collector, kube-state-metrics, node-exporter, Grafana, VictoriaMetrics/VictoriaLogs/vmalert (nuc1), Kepler, Go (bouncer).

**Spec:** `docs/superpowers/specs/2026-10-29-cluster-v3-design.md`

## Global Constraints

- Guiding principle: everything in its most natural and clearest form; no abstraction for its own sake; no in-house CRD layer; uniformity is not a goal.
- microvm.nix, k3s and Tailscale stay. Rewrite in place in `homelab-cluster`, history kept.
- Same purpose for kept apps: site, vitrine, holive, gatus, glance, headscale, open-webui. Removed: umami, oxymore, opencost, headplane.
- Removed platform parts: Traefik, MetalLB, vault-config-operator, Tetragon, Alloy.
- Same access model: Pocket-ID groups `admins` (cluster-admin, Grafana Admin, OpenBao admin) and `visitors` (`view`, Grafana Viewer); Headscale ACLs in `apps/headscale/policy.json` unchanged (including `tag:gamehost`).
- Same addresses: public `${INGRESS_ADDRESS}` = 192.168.1.240, internal `${INTERNAL_ADDRESS}` = 192.168.1.241, pool `${INGRESS_POOL}` = 192.168.1.240-192.168.1.254. Namespace label `gateway-access: public|internal|both` keeps its meaning.
- Every namespace keeps a `CiliumNetworkPolicy`, deny by default in both directions, then what each component needs (README "Network policies" table still applies).
- Observability storage and alerting stay on nuc1. Nothing observability-related is public.
- Every chart, image and CRD bundle pinned to an exact version (latest stable when the task is done); Renovate tracks them.
- Realistic memory requests on every workload (the 2026-10-11 collapse). VM sizes may change only after Task 2's measurements and the owner's review of the numbers.
- Comments: file header comment in the existing style (what the file is, who reaches it, what it reaches). English.
- Git: stage explicit files only, never `git commit -a` (the owner has parallel edits). No `Co-Authored-By` trailer. Do not push without the owner's OK.

## Review Focus

1. **Real client IP behind the Cilium Gateway**: logs, CrowdSec and the ban policy must see the visitor's IP, not a node IP. Test: Task 3 Step 4 and Task 21 Step 5.
2. **Bouncer fail-static**: if LAPI is unreachable or returns an error, existing `CiliumCIDRGroup`s stay as they are (no unban-all, no crash loop deleting groups). Test: Task 8 `TestReconcileKeepsGroupsOnSourceError`.
3. **Database passwords do not change by themselves**: generated once, never rotated by a refresh; a pod restart must not lock an app out. Test: Task 16 Step 6.
4. **OpenBao comes back unsealed after a pod or node restart**, without a human. Test: Task 15 Step 5.
5. **Restarting a VM keeps PostgreSQL's data** (local volume survives; tmpfs root does not matter). Test: Task 11 Step 4 and Task 21 Step 6.
